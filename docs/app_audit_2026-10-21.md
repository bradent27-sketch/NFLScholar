# App audit and speed pass — 2026-10-21

User request: make clicking through the board faster (1a: an injury/QB1 override should not rebuild everything; 1b: no
automatic rebuilds of a board built an hour or two ago), and check every page for what fell behind while the model work went on.

Every page and sub-tab was rendered headless on its default season and on 2026 (`scripts/audit_app_pages.py`, before and after),
the slow paths were profiled, and the main pages were checked in the browser. After the fixes every page renders with no error or
exception on both seasons; the one warning left is Live Odds' note that Playwright isn't installed.

## Speed

| What | Before | After |
|---|---|---|
| Live board build (2026 week 7), first of the session | 116-239 s | 35-80 s |
| Rebuild after an injury / QB1 override | 107 s (minutes under load) | ~20 s |
| Full page rerun on Weekly Rankings with a board built | 7.0 s | 1.7 s |
| Automatic rebuild when the hour-long cache expired | yes, on any full rerun | never (the board is kept until Build board or a changed override) |
| Opening a player in Player Search | a second, separately keyed full build (minutes) | reads the board already built; a button builds it if none |

(Timings with a harness running in the background; an idle machine is faster.) All speed changes are output-neutral: boards
built with the committed code and with the new code are identical in every number and every explanation record (2026 week 7
live and 2025 week 8 backtest; the only differences are row order in two Deep Dive logs, which the display sorts by week, and
last-digit float noise in one display field).

- `data/pff_alignment.py`: the four weekly PFF loaders are memoized in-process and on disk (`data/cache/pff_loads`), keyed by
  their arguments, size and modification time of every file in that season's PFF folder, the schedule's matchups, the module's
  own file and its constants. Per-player alignment/scheme lookups use per-table column maps instead of copying and
  re-normalizing the whole table on each of ~3,500 calls.
- `data/weekly_projections.py`: the partial-game history filter is memoized (content hash of its inputs and thresholds); the
  Deep Dive records are built from one object array instead of `to_dict` (about 9x faster, same values and types).
- `data/availability_overrides.py`: player-ID cleaning without building a one-element Series (~11,000 calls per build).
- `ui/board_session.py` (new): the boards built this session, kept per (season, week, scoring) until Build board is clicked or
  the week's injury/availability overrides or the season's QB1 choices change; the last two selections are kept, so switching
  week or scoring back shows the earlier board without a rebuild. A caption shows when the board was built and nudges a rebuild
  after 3 hours. The ledger records a board once per real build.
- `ui/tabs/rankings.py`: name matching onto the board in whole columns (was ~3,500 single-name calls per full rerun); the QB1
  hub resolves the league once for its 32 team controls (was once per team).

Not done (1a as asked): recalculating only the affected team. A few model steps are league-wide (position share totals and the
per-position normalization), so a team-only recalculation would differ slightly from a full build; with a full rebuild now about
20 seconds the numbers stay exact instead.

## Fixed

| Page | Problem | Fix |
|---|---|---|
| Player Search, Player Compare, Matchup Analyzer | Crashed on 2026 (a playerless nflverse row became a player named 0) | Rows without a player_id dropped at the loader; the picker keeps text names only |
| Seven pages | Opened on 2025 all season (index=1) | Open on the newest season once it has a game played (`default_season_index`) |
| Player Search | Blended the model 70/30 toward market prop lines (against the no-blend rule); its points skipped calibration; it built its own healthy-player board | Model and market shown side by side, never blended; points = the board's Model Proj Pts; reuses the Weekly Rankings board |
| Weekly Rankings QB1 hub, Depth Charts | The QB1 control resolved starters without the shipped QB rules, so PHI showed "No unambiguous QB starter" while the board had McKee | Same rules as the board (latest full-snap start, probable-starter fallback), with its own message for a probable starter |
| Depth Charts | 2026 kept the August Ourlads order all season | Ourlads order only until a season has 3 played weeks |
| Game Slate | Opened on last week from Tuesday to Thursday | Opens on the next week once the last one is complete |
| Rookie Watch | DeVonta Smith (2021 WR) listed as a 2026 rookie (a 2026 rookie DB shares his name); "None" printed in the red-zone columns | Each row's own rookie_year; a name a veteran shares is not a rookie name; numeric red-zone columns |
| Risers, Rookie Watch | Kickers led the lists | Position filter, kickers off by default |
| Defensive Yield | Pass-protection panel empty in-season (PFR posts season summaries after the season) | Summed from PFR's weekly game logs until then (checked on 2025: within 0.4 points of the published pressure %) |
| Sidebar | Checked depth charts / PFF archives for 2027 in October; called 2026 weekly stats "not found"; PFF checks pinned to 2025 | Season being prepared = this year from March; reports the cached nflverse download and the week it reaches |
| 2026 weekly stats | Downloaded with no disk cache (a failure would empty the season); every cold load first opened all fourteen 2019-2025 CSVs | Cached to `data/cache/player_stats_{year}.parquet` (same contract as snap counts); files named for another season are skipped |

## Left as is (noted)

- Defensive Yield's MOF Closed/Open % exists for 2025 only (Sharp Football has no archive) - already captioned on the page.
- Draft HQ takes ~20 s to render; it is a preseason tool, so it was not optimized.
- Player Search's career totals cover completed seasons only (deliberate, per its own docstring).
- The "Live data pulls" hub still renders inside its collapsed expander on every full rerun (~0.7 s); turning it into a toggle
  would remove that, at the cost of one more click to open it.
